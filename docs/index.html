CR7Script 0.1 · Approved language design

A scripting language with its own playbook.

CR7Script gives programming concepts a football vocabulary while keeping evaluation strict, predictable, and documented.

Implementation status: the lexer, parser, resolver, interpreter core, module loader, and standard library are implemented. The supported command-line runner, syntax checker, and REPL are not available yet. Examples on this site describe the approved language contract; they are not CLI instructions.

How CR7Script works

CR7Script is a tree-walking language implemented in Go 1.27 or newer. The host language is Go; CR7Script is not Go syntax and is not transpiled to Go.

  1. UTF-8 source
  2. Lexer
  3. Parser / AST
  4. Resolver
  5. Module loader
  6. Evaluator
  7. Standard library

The resolver checks lexical bindings before evaluation. The loader resolves local and registered modules, initializes dependencies, and detects cycles. The evaluator executes the resolved syntax tree with strict runtime checks.

What the 0.1 contract covers

  • Dynamic values with strict type checks, finite numbers, Unicode text, lists, and ordered dictionaries.
  • Lexical scopes, mutable and non-reassignable bindings, first-class functions, closures, recursion, and loop control.
  • Importer-relative local modules and a fixed registry of standard modules.
  • Stable resolver/runtime error codes and runtime-only recovery that preserves earlier side effects.
  • A standard prelude plus statistics, text, numeric, and sourced-quote modules.

Classes, inheritance, macros, generics, concurrency, network access, package installation, and a security sandbox are outside 0.1.
