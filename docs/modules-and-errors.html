Modules · loading · recovery

Keep modules explicit and failures visible.

CR7Script imports only local .cr7 modules and a fixed standard-library registry. Runtime recovery is deliberately narrow: it handles execution errors but does not undo earlier effects.

Contract, not a runnable CLI guide. Module loading and runtime recovery are implemented in the interpreter core. A supported command-line runner, checker, and REPL are not available, so examples below are illustrative and have not been run as CR7Script programs.

Import a registered module or a relative file

fichar "mr_champions" como champions;
fichar "./jugadas.cr7" como tactica;

jugada comandante() {
    siuuu(champions.soy_el_mejor([7, 10, 17]));
    siuuu(tactica.rematar(7, 10));
}
Import formResolution rule
Registered nameOnly an exact name in the built-in registry resolves; imports do not download packages.
Local pathMust begin with ./ or ../, include .cr7, and is resolved relative to the importing file.
Absolute pathRejected by the language contract.

Imports are top-level and must appear before other module declarations. A module may contain imports, function declarations, and initialized leyenda bindings; executable statements and mutable bindings belong inside functions. Top-level functions initialize before constants, which then initialize in source order.

Initialization is dependency-ordered and cached

  • Local paths are canonicalized through the filesystem, including symlink resolution. The canonical path identifies a local module.
  • Dependencies initialize before their importer. A module initializes once per process and later imports reuse it.
  • Cyclic imports fail with FichajeCircular; the diagnostic includes the import chain.
  • Import aliases are immutable module bindings. A module namespace is read-only, but a list or dictionary exported by reference remains mutable.
  • Importing a standard module does not itself print output or perform module-resolution I/O.
Path resolution is not a sandbox. It determines which local file is imported; it does not isolate an untrusted program or make executing one safe.

remontada catches runtime errors only

jugada penalti(acierto) {
    si no acierto {
        falta "Penalti fallado";
    }
    devuelve "Gol";
}

jugada comandante() {
    remontada {
        siuuu(penalti(fuera));
    } var error {
        siuuu("Revision VAR:", error.codigo, error.mensaje);
    }
}
  • A recovery block has exactly one var identifier handler; the catch binding is immutable and scoped to that handler.
  • falta with text creates FaltaDelUsuario. With an existing error value, it rethrows that error.
  • remontada catches runtime errors from its protected block. It does not catch lexical, parsing, resolver, or module-loading errors.
  • Effects that happened before an error remain. Recovery is not a transaction, rollback, automatic retry, or finally mechanism.
  • devuelve, vestuario, and siguiente are control flow, not catchable errors.

Error values expose read-only codigo, mensaje, archivo, linea, and columna fields. Locations are one-based; columns count Unicode scalar values.
