Practical guidance · explicit boundaries

Make every conversion, mutation, and recovery deliberate.

CR7Script combines dynamic values with strict checks. Prefer small functions, explicit ownership of shared collections, and narrow recovery blocks rather than relying on implicit conversions or hidden side effects.

Approved design, incomplete tooling. The frontend, evaluator/value layer, runtime recovery, loader, and standard library have implementations with focused tests. No supported runner, checker, REPL, or CLI is available yet. All examples on this page are illustrative contract examples, not verified program executions or evidence of production readiness.

Keep value types explicit

  • Use boolean expressions for conditions and y/o; numbers and text are not truthy. si 7 { ... } is invalid.
  • Use numero(text) for decimal input and texto(value) for display conversion. Invalid numeric text raises ConversionInvalida.
  • + accepts two numbers or two texts, not a mixed pair. Write "CR" + texto(7), not "CR" + 7.
  • Lists and dictionaries compare by identity, not recursively by contents. Do not use == as a deep-content comparison.
  • Text length and indexes count Unicode scalar values, not bytes or user-perceived characters. A displayed character may contain multiple scalars.
jugada etiqueta(dorsal) {
    exige(tipo(dorsal) == "numero", "Expected a number");
    devuelve "CR" + texto(dorsal);
}

Keep input validation close to the boundary where a value enters a function. exige raises FaltaDelUsuario when its boolean condition is false; it does not introduce static types.

Plan for finite binary64 arithmetic

Every numero is a finite IEEE-754 binary64 value. Decimal fractions need not be exact. Integers are exactly representable through magnitude 2^53 - 1 (9,007,199,254,740,991); larger integer values may be rounded. This is not a suitable representation for exact financial arithmetic.

  • Do not treat display conversion or rounding as a way to restore precision already lost in a calculation.
  • A non-finite literal such as 1e999 is rejected during frontend analysis with NumeroNoFinito, before execution. A runtime recovery block cannot catch that analysis failure.
  • Arithmetic producing infinity or NaN raises NumeroNoFinito; division and remainder by zero raise DivisionPorCero.
  • 7 / 2 is 3.5, not integer division. Remainder uses truncation toward zero: -7 % 3 is -1.
  • Use non-negative safe integers for indexes and sleep durations. Range bounds must be safe integers; rango allocates a list, so large ranges consume memory.

Use non-reassignable bindings without assuming deep immutability

Prefer leyenda when the binding should not change, and cantera when reassignment is intentional. Neither declaration clones a collection. Function arguments also retain collection identity.

jugada preparar() {
    leyenda plantilla = [7];
    cantera compartida = plantilla;
    convoca(compartida, 10);
    // plantilla and compartida still refer to the same changed list.
    devuelve plantilla;
}
  • Document which functions mutate their list or dictionary arguments. convoca, banquillo, and index assignment change collections in place.
  • chilena(list) returns a new shallow reversed list; nested collections are still shared. hat_trick(value) repeats the same reference three times for reference values, not three independent clones.
  • Use convoca to append. Assigning at a list's length is an out-of-bounds error, not an append operation.
  • Use consulta(dict, key, fallback) when a missing key is expected. A present key containing nada returns nada, not the fallback.
  • Iteration takes a shallow snapshot at loop entry. Do not expect later changes to collection membership to change that traversal; nested referenced values can still change.

Keep module boundaries small and dependencies visible

Place imports first, at module level. Use a registered standard-module name or a local path starting with ./ or ../ and ending in .cr7. Relative paths resolve from the importing file, not the shell's current directory. Absolute imports are rejected and imports never download packages.

  • Put executable statements and mutable bindings inside functions. Module-level declarations are imports, functions, and initialized leyenda bindings.
  • Top-level functions and constants are exported. Keep the public surface intentional; the 0.1 contract has no private-export syntax.
  • Top-level functions initialize first, then constants in source order. Reading a later constant raises the resolver error NombreSinInicializar.
  • Dependencies initialize first, once per process. Cycles are rejected with FichajeCircular; avoid mutually dependent modules.
  • Import aliases and module namespaces are read-only, but exported collection references can remain mutable. A read-only namespace is not a deep-immutability boundary.
  • An imported comandante is an ordinary exported function; importing does not automatically call it.

See modules and errors for initialization and error-phase details.

Recover narrowly; never assume rollback

Use remontada around a runtime operation with a meaningful fallback. Inspect error.codigo rather than parsing human-readable messages. Rethrow unexpected errors with falta error;.

jugada leer_numero(entrada) {
    remontada {
        devuelve numero(entrada);
    } var error {
        si error.codigo == "ConversionInvalida" {
            devuelve nada;
        }
        falta error;
    }
}

This illustrative function deliberately uses nada as its invalid-input result; callers must handle that result explicitly.

  • Recovery catches runtime errors only, not lexical, parsing, resolution, or module-loading failures.
  • Output already printed and collections already mutated stay changed after failure. Validate before mutation where practical; a handler is not a transaction.
  • Recovery does not retry automatically. Repeating a failed operation may repeat earlier effects.
  • Return, break, and continue are control flow, not catchable errors. There is no finally in 0.1.
  • The handler binding and error fields are read-only. Use codigo, mensaje, archivo, linea, and columna for structured context; CLI stack presentation remains pending.

Do not confuse path validation with isolation

Not a security sandbox. CR7Script is learning-oriented. Canonical paths, rejected absolute imports, module caching, and cycle detection do not make untrusted code safe to execute.

Local imports permit ../ and resolve symlinks; these rules do not confine dependencies to a project directory. Review imported source and its dependencies as code, not harmless data. Do not rely on the language runtime to isolate untrusted programs or protect the host.

Execution is single-threaded with host-managed memory. There is no async or parallel syntax. Large collections and ranges consume memory, and calma blocks execution. A call-depth error is not a general resource-isolation guarantee.

The approved 0.1 scope excludes classes, inheritance, operator overloading, macros, generics, threads, network access, package installation, JIT, native code generation, and self-hosting. Slices and destructuring are also unavailable. The standard library offers no filesystem or network API; local module loading still accesses the filesystem.

Read the contract before assuming a tool exists

The approved language reference defines semantics. The architecture and roadmap distinguish implemented packages and observed tests from pending integration. The reference's opening implementation summary is older than those status documents; it is not the current package inventory.

The proposed checker validates syntax and lexical bindings without execution; that guarantee is not proof of runtime success. The runner, checker, REPL, help, and version interfaces remain unavailable. No installation or execution command is supplied here, and documented examples must not be treated as executed fixtures.
